# Analysis specification fixed before the formal campaign

The campaign has not started when this file is written. No evaluation outcomes are used to choose tests or table columns.

1. Validate the frozen code, complete 8 sessions, 32 distinct questions and 576 requests, and check exact token sequence and termination equality of all distributed methods against target-only. Fixed-depth aliases reuse measurements and do not increase the sample size.
2. Score all questions with the frozen first-numeric-answer extractor, with and without fallback. Report paired target-minus-edge accuracy in percentage points; 50,000 paired question bootstrap resamples (seed 2026092802), percentile 95% intervals; two-sided exact McNemar using discordant questions. The strict result is a sensitivity analysis, not an alternative primary endpoint selected after results.
3. Per session, divide summed completion time by summed delivered tokens. Report the mean of these 8 session ratios and its t interval (7 degrees of freedom). Planned SN-minus-comparator contrasts use paired differences of these ratios, two-sided paired t tests and one Holm family of 8 (4 comparators by 2 paths). Also report exhaustive paired sign-flip sensitivity tests over the 256 sign assignments; these require symmetry/exchangeability and are not distribution-free evidence. Small-sample t assumptions and limited deployment generality must remain explicit.
4. Report mean E2E, TTFT, output tokens and empirical request p95 descriptively. Request p95 is based on 32 requests and is not a precise population tail estimate. Do not confuse round tails with request tails. Include completion reason, cap rate and task correctness for every delivered-method row.
5. Report application payload bytes, verification round counts, total verification RPC time and RPC-minus-reported-server-verification residual per request. Residual includes protocol/client/server overhead and is not pure network propagation. Target-only has no verification RPC; its verification columns are NA. Edge-only has zero cloud interaction. Separately report target-stream E2E-minus-server-total as a protocol-specific residual, not an interchangeable RTT measure.
6. Resource telemetry may only be integrated for request intervals bracketed by real samples; do not extrapolate missing boundary samples. Its coverage must be reported explicitly. Edge generation/commit wall time and pure GPU compute time are different quantities.
7. Preserve original Table 4. Produce a separately labelled H<=512 answer-completion table with all B1-B6 aliases, SN, the three UCB comparators, target-only and edge-only. A quality advantage of exact cloud collaboration is shared by all exact methods; it is not evidence that SN improves model weights or uniquely improves accuracy.
